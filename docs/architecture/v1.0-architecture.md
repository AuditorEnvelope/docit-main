# Lekhak AI Architecture Documentation
=====================================

## System Architecture Overview
-----------------------------

Lekhak AI is a production-grade documentation platform that transforms code analysis into structured, searchable documentation. The system processes Git commits, analyzes code patterns, and generates documentation with AI assistance. The architecture is designed to be scalable, modular, and maintainable.

### High-Level Architecture

The Lekhak AI system consists of the following main components:

* **Event Consumer**: Processes GitHub webhooks and analyzes commits
* **Smart Processor**: AI-powered code analysis
* **Database**: Stores documentation data and metadata
* **API**: Exposes endpoints for documentation generation, search, and retrieval

## Main Components and Modules
------------------------------

### 1. Event Consumer

* **Description**: The Event Consumer is responsible for processing GitHub webhooks and analyzing commits.
* **Modules**:
	+ `event_consumer.py`: Handles GitHub webhooks and triggers commit analysis
	+ `commit_bus.py`: Analyzes commits and extracts relevant data
* **Dependencies**:
	+ `github_sync.py`: Utility module for GitHub API interactions

### 2. Smart Processor

* **Description**: The Smart Processor is responsible for AI-powered code analysis.
* **Modules**:
	+ `universal_code_parser.py`: Parses code and extracts relevant data
	+ `quality_checker.py`: Checks code quality and generates insights
* **Dependencies**:
	+ `canonical_model.py`: Provides a canonical model for code analysis

### 3. Database

* **Description**: The Database stores documentation data and metadata.
* **Modules**:
	+ `database.py`: Provides a database interface for data storage and retrieval
* **Dependencies**:
	+ `postgresql`: Database management system

### 4. API

* **Description**: The API exposes endpoints for documentation generation, search, and retrieval.
* **Modules**:
	+ `api.py`: Provides API endpoints for documentation generation, search, and retrieval
	+ `webhook/route.ts`: Handles GitHub webhooks and triggers documentation generation
	+ `repositories/route.ts`: Handles repository-related API requests
	+ `generate-docs/route.ts`: Handles documentation generation API requests
	+ `search/route.ts`: Handles search API requests
	+ `fetch-doc/route.ts`: Handles documentation retrieval API requests
* **Dependencies**:
	+ `express`: Web framework for API development

## Data Flow
-------------

The data flow in Lekhak AI is as follows:

1. **GitHub Webhook**: GitHub sends a webhook notification to the Event Consumer when a commit is made.
2. **Commit Analysis**: The Event Consumer analyzes the commit and extracts relevant data.
3. **Code Analysis**: The Smart Processor analyzes the code and generates insights.
4. **Documentation Generation**: The API generates documentation based on the code analysis results.
5. **Documentation Storage**: The Database stores the generated documentation.
6. **Search and Retrieval**: The API provides endpoints for searching and retrieving documentation.

## Dependencies and Relationships
-------------------------------

The dependencies and relationships between components are as follows:

* **Event Consumer** depends on **GitHub Sync** for GitHub API interactions.
* **Smart Processor** depends on **Canonical Model** for code analysis.
* **Database** depends on **PostgreSQL** for database management.
* **API** depends on **Express** for web framework development.
* **API** depends on **Event Consumer** for documentation generation triggers.
* **API** depends on **Smart Processor** for code analysis results.

## Design Patterns Used
-----------------------

The following design patterns are used in Lekhak AI:

* **Modular Design**: The system is designed to be modular, with each component having a specific responsibility.
* **Dependency Injection**: Dependencies are injected into components to reduce coupling and increase maintainability.
* **Observer Pattern**: The Event Consumer uses the Observer pattern to handle GitHub webhooks and trigger commit analysis.
* **Factory Pattern**: The Smart Processor uses the Factory pattern to create code analysis results.
* **Repository Pattern**: The Database uses the Repository pattern to provide a database interface for data storage and retrieval.
