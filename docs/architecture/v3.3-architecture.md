The system's data flow appears to be event-driven, centered around code analysis and documentation generation, aligning with the "Event-driven processing pipeline" and "4-stage data flow from webhook to Git commit" mentioned in recent documentation changes.

1.  **Ingestion/Event Trigger**: External events, potentially webhooks (as inferred from "4-stage data flow from webhook"), are received by the API (likely managed through `main.py` using `FastAPI`). These events could represent code changes or other triggers.
2.  **Event Processing**: The `event_consumer` utility likely picks up these events, which might be routed through the `commit_bus` for reliable, asynchronous processing. This bus could coordinate actions related to code commits or other system events.
3.  **Core Intelligence & Processing**:
    *   `github_sync` is utilized to fetch relevant codebases or changes from GitHub.
    *   The `universal_code_parser` then processes this code, extracting structured information.
    *   `llm_provider_v2` and `lekhak_ai_integration` integrate Large Language Models for advanced analysis, code understanding, or content generation.
    *   The `smart_processor` likely orchestrates these analysis steps, applying business logic and potentially leveraging `canonical_model` for data representation.
    *   Specific services like `indexer_service` might process and store extracted data for efficient retrieval (e.g., in `Milvus` for semantic search).
    *   `agent_service` and `overlay_service` might act upon this processed intelligence to provide automated actions or UI overlays.
4.  **Data Persistence**: Processed data and generated artifacts are stored across the various `database` technologies, with `asyncpg` used for PostgreSQL, and `pymilvus` for Milvus, depending on the data type and access patterns.
5.  **Output & Presentation**:
    *   `hierarchical_doc_generator` and `comprehensive_doc_generator` generate detailed documentation based on the analyzed code and LLM insights.
    *   The `frontend` (`pustak`) consumes these generated documents or interacts with the API/services to present information to users.
    *   `subscription_service` manages user subscriptions and access to system features.
