## Data Flow

Data flow within the `docai_smart_j4v44b6e` system begins at the **Frontend (pustak)**. User interactions, such as requesting repository listings or viewing documentation, trigger API calls to the **Backend API (src/main.py)**.

1.  **Authentication Flow**: Frontend routes like `pustak/src/app/auth/callback/page.tsx` handle OAuth2 callbacks, receiving and storing a user's GitHub token in a client-side cookie (`github_token`). Subsequent API requests from the frontend to the backend include a JWT `Authorization` token, validated by `src/auth_service.py`.

2.  **GitHub API Proxying**: Frontend calls to `/api/repositories` (e.g., `pustak/src/app/api/repositories/route.ts`) are proxied through the backend. The backend's `src/main.py` (potentially interacting with `src/github_sync.py`) uses the user's stored `github_token` to make authenticated calls to the actual GitHub API. This centralizes GitHub interactions and enables user-specific data retrieval.

3.  **Core Processing**: Upon receiving authenticated requests, `src/main.py` dispatches to various services and utilities.
    *   `universal_code_parser.py` might process code from GitHub.
    *   `indexer_service.py` could take this parsed code and generate embeddings, storing them in **Milvus** for a RAG system.
    *   `llm_provider_v2.py`, `lekhak_ai_integration.py`, `smart_processor.py` integrate with external and internal AI models for tasks like analysis or content generation.
    *   `hierarchical_doc_generator.py` and `comprehensive_doc_generator.py` consume processed data to generate documentation, which might be served back to the frontend.
    *   `quality_checker.py` and `quality_integration.py` ensure the integrity and standards of generated content or processed code.

4.  **Event-Driven Operations**: Long-running or asynchronous tasks might leverage `commit_bus.py` to publish events, which are then consumed by `event_consumer.py`. This pattern likely involves **PostgreSQL** (via `asyncpg`) for event persistence or state management.

5.  **Data Persistence**: Services interact with various **Database** technologies. `canonical_model.py` defines the data structure for persistence in databases like PostgreSQL, MySQL, SQLite, MongoDB, or Redis, depending on the data type and access patterns.

6.  **External Integrations**: `stripe_service.py` handles financial transactions. `webhook_handler.py` processes incoming webhooks from external services (like GitHub or Stripe), triggering internal processes.

## Recent Changes Impact

The v3.7 update represents a significant architectural shift with a primary focus on `Multi-Organization Authentication and Frontend Rearchitecture`.

1.  **Authentication System Overhaul**: The system has moved to a robust, `backend-driven OAuth2 and JWT authentication system`. This is a foundational change enabling multi-user and multi-organization support. `src/auth_service.py` and `src/main.py` are now central to managing user identity and access tokens. The `pustak/src/app/auth/callback/page.tsx` now plays a critical role in handling the GitHub OAuth callback and securing the `github_token` in a client-side cookie.

2.  **Centralized GitHub API Interaction**: All GitHub API interactions are now **proxied through the authenticated backend**. This means the frontend (`pustak/src/app/api/repositories/route.ts`) no longer makes direct calls to GitHub via `realGitHubAPI.ts` but acts as an authenticated proxy to a new backend endpoint (`${BACKEND_URL}/auth/repositories`). This design choice enhances security, allows for rate limiting, and facilitates user-specific data filtering and authorization based on the user's `github_token` and JWT.

3.  **Frontend Rearchitecture**: The frontend, residing in the `pustak` directory, has undergone a comprehensive overhaul. The removal of `pustak/src/app/api/docs/[repoName]/route.ts`, `pustak/src/app/repo/[repoName]/...`, `pustak/src/components/Sidebar.tsx`, and related utility files (`githubAPI.ts`, `markdownLoader.ts`, `searchAPI.ts`, `simpleRepoLoader.ts`) indicates a complete shift in how documentation content is loaded, routed, and displayed. The introduction of `pustak/src/components/EnhancedSidebar.tsx` and `pustak/src/components/Layout.tsx` suggests a new, more dynamic, and backend-driven UI for viewing documentation, likely fetching content via the newly authenticated backend API rather than directly from GitHub or local markdown files.

4.  **Impact on Backend Modules**: `src/auth_service.py` is now a critical component for managing tokens and user sessions. `src/main.py` has expanded its role to include new API endpoints for handling authenticated repository listings and potentially serving documentation content. `src/doc_generation_endpoint.py` may also have been updated to align with the new authentication and content delivery mechanisms.

5.  **Breaking Changes**: The complete change in frontend routing and API interaction patterns constitutes *breaking changes*, requiring a migration guide for any existing consumers or developers. The architectural shift is highly significant, laying the foundation for advanced multi-organization capabilities.
