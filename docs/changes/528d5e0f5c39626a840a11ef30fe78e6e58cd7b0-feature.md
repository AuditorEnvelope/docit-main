# Multi-Org Support Feature Documentation
=====================================

## **Overview**
### Introduction

This document outlines the changes made to implement multi-organization support in our system. The primary goal of this feature is to provide users with the ability to manage multiple organizations, each with their own set of repositories and documents. This change affects core system functionality and security, making it a significant addition to our platform.

### Reasoning

The need for multi-organization support arose from the growing demand for a more flexible and scalable system. By introducing this feature, we aim to enhance the overall user experience, improve data organization, and provide a more secure way to manage user-specific data.

## **Impact**
### Affected Components

The following components have been modified to support multi-organization functionality:

* `pustak/src/app/`: Updates to the application's core logic
* `pustak/src/components/`: Changes to frontend components to handle user-specific data
* `pustak/src/contexts/`: Modifications to the authentication context
* `pustak/src/lib/`: Updates to the library to support authenticated API requests

### Impact Scope

The changes made have an impact on the following areas:

* **Authentication**: Updates to the authentication context to handle user-specific data
* **API**: Changes to API requests to support authenticated and user-specific data retrieval
* **Frontend**: Modifications to frontend components to display user-specific data and repositories

## **New Features**
### Multi-Organization Support

The primary feature added is the ability for users to manage multiple organizations, each with its own set of repositories and documents.

### User-Specific Repository Handling

Users can now access and manage their own repositories, which are specific to their organization.

### Authenticated API Requests

API requests are now authenticated using JWT tokens, ensuring secure access to user-specific data.

## **Breaking Changes**
### Changes and Migration Steps

1. **Update Authentication Context**: Update the authentication context to handle user-specific data.

## **Technical Details**
### Implementation

The implementation involves changes to the authentication context, API requests, and frontend components to handle user-specific data and repositories. The use of JWT tokens and authenticated API requests ensures secure access to user data.

### Authentication Context

The authentication context has been updated to handle user-specific data, including organization-specific repositories and documents.

### API Requests

API requests have been modified to support authenticated and user-specific data retrieval. JWT tokens are used to authenticate requests and ensure secure access to user data.

## **Usage Examples**
### Creating a New Organization

To create a new organization, follow these steps:

1. Log in to the system using your credentials.
2. Click on the "Create Organization" button.
3. Enter the organization name and description.
4. Click "Create" to create the new organization.

### Accessing User-Specific Repositories

To access user-specific repositories, follow these steps:

1. Log in to the system using your credentials.
2. Click on the "Repositories" tab.
3. Select the organization for which you want to access repositories.
4. Click on the repository you want to access.
