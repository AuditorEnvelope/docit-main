# Documentation: Recursive File Detection Depth Control for Doc Parsing

## 1. Overview

This document outlines a significant feature addition that introduces granular control over the maximum recursion depth during hierarchical documentation parsing. This enhancement aims to improve the structure, performance, and configurability of documentation generation, especially for repositories with deeply nested file structures.

The core motivation behind this change is to empower users to manage the complexity and computational overhead associated with parsing extensive directory trees. By setting a maximum depth, users can tailor the generated documentation to focus on relevant levels of hierarchy, preventing the inclusion of overly deep or irrelevant file paths, and consequently optimizing both generation time and the resulting documentation size.

## 2. Impact

This feature has a broad impact across the documentation system, affecting key areas:

*   **Documentation Generation**: The backend logic for parsing repositories and identifying documentation files is directly modified to respect the new depth limit. This affects how documentation is structured and what files are included.
*   **Frontend Display**: The user interface for viewing documentation, specifically the hierarchical document tree, is updated to correctly display content based on the configured maximum depth.
*   **CLI Configuration**: Users can now configure the recursion depth directly via a new command-line argument, making the feature easily accessible and controllable.

**Affected Components:**

*   `src/hierarchical_doc_generator.py`: The core backend logic responsible for recursively traversing directories and identifying files for documentation.
*   `src/main.py`: The command-line interface (CLI) entry point, which now supports a new argument for depth control.
*   `pustak/src/app/repo/[repoName]/[docType]/page.tsx`: The frontend component responsible for rendering the documentation viewer and its associated document tree.

## 3. New Features

This change introduces the following new functionalities:

*   **Configurable Maximum Recursion Depth for Hierarchical Document Parsing**: A new option is available to specify the maximum directory recursion depth during the documentation generation process. This is exposed via a new `--max-depth` argument in the CLI. By default, the system will recurse up to 5 levels deep if not explicitly specified.
*   **Frontend Document Tree Depth Awareness**: The `DocumentTree` component in the frontend now accepts and utilizes a `maxDepth` prop. This ensures that the visual representation of the documentation hierarchy aligns with the depth limit set during the backend generation, providing a consistent user experience.

## 4. Breaking Changes

There are **no breaking changes** introduced with this update. The existing functionality will continue to work as before, utilizing the default recursion depth if the new `--max-depth` argument is not provided.

## 5. Technical Details

The implementation of this feature involved modifications across both backend and frontend components:

*   **Backend Logic (`src/hierarchical_doc_generator.py`):**
    *   A new constant, `MAX_DIR_RECURSION_DEPTH`, has been introduced, defaulting to `5`. This constant defines the default maximum depth for directory traversal when no explicit depth is provided.
    *   The core recursive function `_get_nested_files_and_dirs` has been updated. It now accepts an additional `max_depth` parameter and a `current_depth` parameter. The function will terminate its recursion early for any given path if `current_depth` exceeds `max_depth`.
    *   The `max_depth` parameter passed to `_get_nested_files_and_dirs` is derived from the CLI argument or defaults to `MAX_DIR_RECURSION_DEPTH`.

*   **CLI Argument Parsing (`src/main.py`):**
    *   The `argparse` configuration in `src/main.py` has been extended to include a new optional argument: `--max-depth`.
    *   This argument expects an integer value representing the desired maximum recursion depth.
    *   The value provided via `--max-depth` is then passed down to the `hierarchical_doc_generator.py` module when initiating the documentation generation process.

*   **Frontend Display (`pustak/src/app/repo/[repoName]/[docType]/page.tsx`):**
    *   The `page.tsx` component now explicitly passes a `maxDepth={5}` prop to the `DocumentTree` component. This ensures that the frontend's default visual depth matches the backend's default generation depth for consistency. While the backend generated data will inherently respect the depth, this prop provides a consistent understanding within the frontend component.
    *   As part of the same commit, the frontend logic was also refactored to use a `repoPath` state, derived from `params.repoName`, to improve consistency and maintainability across the component. This is a minor refactoring alongside the main feature.

## 6. Usage Examples

The new maximum recursion depth can be controlled via the `--max-depth` command-line argument when invoking the documentation generation script.

**Default Behavior (no `--max-depth` specified):**
The system will use the default `MAX_DIR_RECURSION_DEPTH` of `5`.

```bash
python src/main.py generate --repo /path/to/your/repository --output /path/to/output/docs
```

**Specifying a Custom Depth:**
To limit the documentation generation to a specific number of directory levels (e.g., 2 levels deep):

```bash
python src/main.py generate --repo /path/to/your/repository --output /path/to/output/docs --max-depth 2
```

This command will generate documentation that includes files and directories up to 2 levels deep from the repository root. Any files or directories nested deeper than 2 levels will be ignored during the parsing process.

**Example with a hypothetical repository structure:**

Consider a repository with the following structure:

```
my-repo/
├── README.md
├── src/
│   ├── main.py
│   └── utils/
│       └── helpers/
│           └── math_operations.py
├── docs/
│   └── architecture.md
└── tests/
    └── unit/
        └── test_main.py
```

*   **`--max-depth 0`**: Only `README.md` (root level files) would be considered.
*   **`--max-depth 1`**: `README.md`, `src/`, `docs/`, `tests/` would be considered. Inside `src/`, `main.py` would be considered.
*   **`--max-depth 2`**: `README.md`, `src/`, `docs/`, `tests/`. Inside `src/`, `main.py`, `utils/`. Inside `docs/`, `architecture.md`. Inside `tests/`, `unit/`.
*   **`--max-depth 3`**: All files and directories listed above, including `helpers/`, `math_operations.py`, `test_main.py`.

## 7. Testing

To ensure the new feature works as expected, the following test scenarios should be covered:

1.  **Default Depth Validation:**
    *   **Action:** Run the documentation generation command without the `--max-depth` argument.
    *   **Expected Outcome:** The generated documentation (and the corresponding `DocumentTree` in the frontend) should reflect a recursion depth of 5. Verify that files/directories deeper than 5 levels are *not* included.

2.  **Explicit Depth Limit (`--max-depth N`):**
    *   **Action:** Run the documentation generation command with `--max-depth` set to a specific value (e.g., `1`, `2`, `3`).
    *   **Expected Outcome:**
        *   The generated documentation should accurately reflect the specified depth. Files and directories beyond `N` levels deep should be excluded.
        *   Verify the frontend `DocumentTree` displays the content correctly, truncated at the specified depth.
    *   **Specific Case: `--max-depth 0`**: Only files directly at the repository root should be parsed. No subdirectories or files within them should appear.

3.  **Edge Cases:**
    *   **Action:** Test with a `--max-depth` value that is greater than the actual deepest directory in the repository.
    *   **Expected Outcome:** The system should parse all available directories/files without errors, up to the natural depth of the repository, effectively behaving as if no limit was set.
    *   **Action:** Test with invalid input (e.g., `--max-depth -1`, `--max-depth abc`).
    *   **Expected Outcome:** The CLI parser should handle these gracefully, typically raising an `argparse` error.

4.  **Frontend Display Consistency:**
    *   **Action:** Generate documentation with various `--max-depth` values, then view them in the frontend.
    *   **Expected Outcome:** The visual `DocumentTree` should consistently match the depth of the data generated by the backend, correctly omitting deeper elements if they were not generated.

## 8. Migration Guide

This change introduces a new feature without altering existing functionality or requiring any changes to current configurations or workflows. Therefore, **no migration steps are required**. Existing users can continue to generate documentation as before, and the system will default to a recursion depth of 5. Users who wish to utilize the new depth control can do so by simply adding the `--max-depth` argument to their generation commands.
